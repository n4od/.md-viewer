# Architecture

How the project is put together: the files, the Rust render path that does the
work, and the three static frontend files that draw it. Rust and the frontend are
described separately because the boundary between them is the whole design.

## The Rust backend


One file, five responsibilities.

### Capturing the startup path

```rust
let startup_path = parse_cli_path(&std::env::args().collect::<Vec<_>>());
```

`parse_cli_path` skips `argv[0]`, skips switches (`-x`, `--flag`) unless they
follow `--`, unwraps `file://` URLs and quoted paths, and prefers a file whose
extension is Markdown over any other existing file.

Each section of the backend reads as follows:

| Section | What it does |
| :-- | :-- |
| `parse_cli_path` | Startup/double-click argument resolution. |
| `read_source` | Reads with a 16 MB ceiling, reports truncation, decodes UTF-8/UTF-16 BOMs, degrades lossily. |
| `render_markdown` | `pulldown-cmark` (CommonMark + GFM tables, task lists, strikethrough, footnotes, alerts, definition lists, front-matter suppression) → HTML. |
| `sanitize` | `ammonia` allow-list pass over that HTML. |
| `load_document` | Bundles rendered HTML + metadata (name, folder, size, mtime, words, lines) into the `Document` payload. |
| `prepare_document` | Marks the file as current, grants the asset scope for its folder, sets the window title, starts the watcher. |
| `watch_file` | `notify` on the **parent folder** with a 180 ms debounce → emits `md://reload`. |
| commands | `ready`, `initial_document`, `load_path`, `reload`, `open_dialog`, `open_link`. |
| `run()` | Plugin registration, setup hook, webview drag & drop, window creation. |

### Startup handshake (why launching feels instant)

```rust
.setup(move |app| {
    if let Some(path) = startup_path.clone() {
        let document = prepare_document(&handle, &path);   // read + render now…
        *handle.state::<Viewer>().initial.lock().unwrap() = Some(document);
    }
    // …and show the window only after the frontend says it has painted.
})
```

The file is read and rendered **while the webview is still starting**. The
window is created with `"visible": false`; `app.js` calls the `ready` command
after its first render, and Rust shows and focuses the window. A three-second
watchdog shows it anyway if the frontend ever fails to boot, so the app can
never end up invisible.

### IPC surface

Commands (webview → Rust):

| Command | Returns | Used for |
| :-- | :-- | :-- |
| `ready` | — | "first paint done, show the window". |
| `initial_document` | `Document?` | The document rendered at startup. |
| `load_path(path)` | `Document` | Recent-files list, relative links, switching tabs. |
| `reload` | `Document?` | `Ctrl+R` / `F5`. |
| `filter_existing(paths)` | `Vec<String>` | Prunes recent entries whose file has been moved or deleted. |
| `open_dialog` | `Document?` | `Ctrl+O` (and drag & drop, which goes through the same path). |
| `open_link(href)` | `LinkOutcome` | Link clicks: external → OS browser, sibling `.md` → open in place, missing → notice. |
| `make_default` | `DefaultReport` | Registers MD Viewer as a `.md` handler (writing the document icon out too), tells the shell, then shows the Windows picker. |
| `default_status` | `DefaultStatus` | Whether MD Viewer currently owns `.md`, and which extensions it claims — drives the empty-state line and the Settings panel. |
| `app_version` | `String` | The About line in Settings, read from the binary so it cannot drift. |
| `set_remember_geometry(on)` | — | Whether to carry the window's size and position across launches. |

Events (Rust → webview):

| Event | Payload | Source |
| :-- | :-- | :-- |
| `md://open` | `Document` | second instance launched with a path, file dropped on the window |
| `md://reload` | `Document` | file changed on disk |
| `md://error` | `{ message }` | unreadable drop target, failed open |
| `md://notice` | `{ message }` | "Reloaded from disk" |
| `md://drag` | `{ active }` | drag hover overlay |

### One instance, many tabs

`tauri-plugin-single-instance` is registered *first* (as its docs require). When
a second launch happens — the user double-clicks another `.md` file while the
viewer is running — Windows forwards the new process's argv to the running
instance, which loads the file, emits `md://open`, and focuses the window.

The frontend turns that document into a tab. Opening a file that is already a tab
activates it instead of duplicating it, so a second double-click is safe. Rust still
tracks exactly one active document: switching a tab is just `load_path`, which
re-points the file watcher, the asset scope and the window title at that document.

The strip behaves like a real tablist rather than a row of links: each tab reports
`aria-selected`, the strip is a single tab stop with a roving `tabindex`, and left/right
plus Home/End activate as they move. `Ctrl+Tab` and `Ctrl+Shift+Tab` walk it and wrap,
`Ctrl+W` closes the document you are reading, and a middle-click closes the one under the
pointer. Because the strip is rebuilt whenever the tab set changes, the renderer records
which control had focus and puts it back — without that, the first switch dropped focus
to the page and the strip could not be navigated again.

The tab set is stored in `localStorage` under `mdviewer.tabs`, and *Reopen the documents
I had open* restores it at start-up (twelve at most). Only the document that was on screen
is read then; the rest are placeholders that load the first time you switch to them, and
any whose file has since moved or been deleted are pruned first. A file named on the
command line still wins over the stored session, so a double-click is never overridden by
what was open last time.

### Live reload

Editors save atomically (write temp file, rename over the original), which kills
a watch registered on the file itself. This app therefore watches the parent
folder, ignores every path that is not the current document, debounces 180 ms of
event noise, and re-renders in place while preserving the scroll position.

### Why the sanitizer is not optional

The webview can call the commands above, so injecting script into a rendered
document would be privilege escalation. Raw HTML in a Markdown file therefore
goes through ammonia's allow-list: no `<script>`, `<iframe>`, `<svg>`, `<form>`,
no `on*` handlers, no `javascript:`/`data:` URLs, and every inline `style` is
dropped. Table alignment does not depend on inline CSS: the renderer's
`text-align` becomes an `align-left|center|right` class before sanitising, so it
works under the app's own CSP.
Paths from `open_link` are executed through the OS opener only after a scheme
check, and `object-src`/`base-uri`/`form-action` are disabled in the CSP as well.

## The frontend


No npm dependencies are used at runtime. Tauri injects `window.__TAURI__`
(`withGlobalTauri: true`), which `app.js` wraps in three lines:

```js
var T = window.__TAURI__ || {};
var invoke = (T.core && T.core.invoke) || function () { return Promise.reject(new Error("Tauri IPC unavailable")); };
var listen = (T.event && T.event.listen) || function () { return Promise.resolve(function () {}); };
```

Flow of a document:

1. `invoke("initial_document")` (or an `md://open` / `md://reload` event) yields
   `{ path, name, dir, html, words, lines, modified, truncated, error }`.
2. `render()` swaps `html` into the article, then `enhance()` post-processes it:
   slug + `id` on every heading (so the outline can link to them), tables wrapped
   in a scroll container, fences wrapped in a block with a language label and a
   copy button, task-list items classed for styling.
3. `rewriteLocalImages()` sends relative `img[src]` through
   `convertFileSrc()` so `./images/shot.png` is served by Tauri's asset protocol
   (the folder was scoped by Rust when the document opened). `http(s)` images —
   README badges — are left alone.
4. `buildToc()` fills the outline drawer; a scroll handler drives the reading
   progress bar and the outline's active item; `updateFooter()` shows the path
   and timestamp.
5. `invoke("ready")` reveals the window.

Extras implemented in plain JS:

* **The window is frameless, so the toolbar is the title bar.** `decorations` is off in
  `tauri.conf.json`, and the 48px `#topbar` carries everything a caption would: the band
  is a drag region (`data-tauri-drag-region="deep"`, which also gives double-click to
  maximize), the document name appears at its left as `.win-title` whenever the tab
  strip is hidden, and three window buttons sit at its right edge. Tauri's drag handler
  ignores clicks on anything clickable, so the tabs and buttons need no marker of their
  own; the buttons call `getCurrentWindow()` from `@tauri-apps/api`, which arrives as
  `window.__TAURI__.window` and is absent in a browser, where they go inert instead of
  throwing. The maximize glyph follows the *window's* state (`isMaximized()` plus the
  resize event) rather than whichever control was clicked, so `Win+↑` and a double-click
  on the band keep it honest.

* **The reading surface is the scroll container.** The page itself never scrolls: `html`
  and `body` are a fixed-height flex column and `#main` scrolls, with the pinned section
  bar a fixed overlay just below the toolbar. That is what puts the scrollbar below the
  toolbar and lets the toolbar — the window's title bar — span the full width, with the
  window buttons flush against the window edge. Everything that reads or moves the reading
  position goes through the `readingTop()`/`readingTo()` helpers, because scroll events
  fire on `#main` rather than on the window.

* **Preview harness.** `src/index.html`, `styles.css` and `app.js` also run in a
  plain Chromium browser: `node scripts/dev-server.js`, then open
  <http://localhost:8123/preview/harness.html> (`preview/wide.html` forces a
  1280×900 viewport for desktop-layout checks). The harness fakes
  `window.__TAURI__`, so typography and interactions can be iterated on without
  rebuilding Rust.

* **Theme** resolved in `<head>` before first paint, stored in `localStorage`,
  cycled with `Ctrl+Shift+L` between *system → light → dark* and re-resolved when
  the OS flips (the CSS uses explicit `[data-theme]` token blocks, no duplication).
* **Find** (`Ctrl+F`, Enter/Shift+Enter, Esc) built on the CSS Custom Highlight
  API: matches are highlighted without mutating the DOM. Match-case and whole-word
  toggles (`Alt+C` / `Alt+W`) persist, and the counter stays accurate past the
  1500-highlight cap.
* **Reading size** (`Ctrl` + `+` / `-` / `0`, or `Ctrl` + wheel) scales the article
  through the
  `--reading-scale` custom property.
* **Recent files** list on the empty state, kept in `localStorage`.
* **Reading position** remembered per document, so a long file reopens where you
  stopped. The first scroll of a burst is written immediately and the resting
  position follows after a short debounce; the map is capped at 60 documents.
* **Tabs** for several documents in one window, with a real tablist model: roving
  `tabindex`, left/right and Home/End, `Ctrl+Tab` / `Ctrl+Shift+Tab` (wrapping),
  `Ctrl+W` to close the document being read, and middle-click to close the tab under
  the pointer. Focus is restored after the strip rebuilds, and the tab set is stored so
  *Reopen the documents I had open* can rebuild it.
* **Accessibility**: skip-to-content link, focus moved into and out of the outline
  and find bar, labelled icon buttons, `aria-expanded`/`aria-current` where they
  apply, and WCAG AA contrast for muted text in both themes.
* **Drag & drop**: Rust emits `md://drag`, the frontend only paints the overlay.
* **Scroll**: `J` / `K` page-scroll, smooth scrolling, `scroll-margin-top` so
  headings never hide under the sticky top bar, and `prefers-reduced-motion`
  honoured.
